# Best practices — выполненные изменения

Дата: 31 октября 2026. Изменения подготовлены локально; production не обновлялся.

## Что изменено

- Общий header, мобильное меню и footer для всех маршрутов. Escape закрывает мобильное меню с возвратом фокуса. Закрытое меню не попадает в tab-порядок.
- Один main landmark с рабочим skip link. Главная явно называет Plumbing, Heating & HVAC и British Columbia; основные действия — Request a Quote и Call.
- Hero и projects: Pause/Play, остановка при фокусе/наведении, reduced motion. В карусели проектов отображается одна доступная карточка, без фокуса на уехавших за экран ссылках. Исправлен /projects/ridgevie.
- Фоновое видео больше не стартует автоматически, preload=none. Для логотипов добавлена пауза. Навязчивое автоматическое открытие maintenance popup на главной отключено.
- Изображения Cloudinary используют f_auto, q_auto и ограничение ширины; hero — srcset, sizes, размеры и fetchPriority=high для первого изображения. Убрана галерея с sample_*.jpg.
- Contact и Quote используют существующий Formspree endpoint из src/config.ts. Успех принимается только при HTTP success + JSON {ok:true}. Убраны фальшивые ticket и имитация успеха при ошибке. Есть timeout 30 s, понятные ошибки, сохранение полей при ошибке, блокировка на время отправки, live region. В Quote — проверка количества/типа/размера файлов на клиенте и освобождение blob URL.
- Автозаполнение полей, type=tel, подписи полей, доступный загрузчик и удаление вложений на touch/клавиатуре. Нативная валидация фокусирует первое невалидное поле.
- Добавлена страница Privacy Notice, описывающая фактическую работу contact/quote и сторонние ресурсы. Это техническое описание текущей реализации, не подтверждение внутренних сроков хранения компании.
- Единый источник метаданных src/data/seo.json. Сборка создаёт 22 HTML-страницы с индивидуальными title, description, canonical, Open Graph и Twitter metadata, sitemap, 404.html и файл алиасов _redirects.
- Canonical и sitemap используют https://www.alliedplumbing.ca. Убраны неподтверждённые aggregateRating, часы и координаты из исходной schema; оставлены базовые данные компании.
- Source public/sitemap.xml, который был изменён до этой работы, сохранён без дальнейших изменений: актуальный sitemap генерируется в dist.
- Восстановлен запускаемый ESLint config в корне. Старый файл src/eslint.config.js с пробелом в имени не использовался npm run lint.

## Аналитика

События добавляются в window.dataLayer, без подключения стороннего трекера:

- phone_click — нажатие tel-ссылки;
- form_start — первое взаимодействие с contact/quote;
- generate_lead — только после подтверждения Formspree;
- form_error — ошибка сети или сервиса;
- web_vital — LCP, INP, CLS через официальную библиотеку web-vitals; отчётность по жизненному циклу страницы.

Поля: form_name, metric_name, metric_value, metric_rating, metric_id, error_type. Имена посетителей, email, телефоны, адреса, сообщения, имена файлов и query string не передаются. Подтверждение Formspree означает приём сервисом; оно не доказывает доставку в почтовый ящик или создание заказа в CRM.

Для сбора в GA4 нужен реальный GA4/GTM ID и согласованная схема consent. После подключения контейнера: создать Custom Event triggers для перечисленных событий, сопоставить поля и отметить generate_lead как key event. Сейчас события доступны локально, но в GA4 не отправляются. Не включать сбор данных форм и PII в GTM.

## Что требуется перед публикацией

1. Подтвердить владение существующим Formspree endpoint xblzarjb и его получателя. Проверить доставку контрольного сообщения с согласованным тестовым адресом. Проверить поддержку вложений на текущем тарифе, ограничения сервера и защиту от спама. Клиентская проверка файлов не заменяет серверную.
2. Подключить реальный GA4/GTM ID, если нужна удалённая аналитика. Обновить privacy notice под реально подключённую аналитику и внутренние правила хранения.
3. Настроить на хостинге перенаправления вариантов домена на www, корректные 301 и HTTP 404. В dist подготовлен Netlify-совместимый _redirects без SPA catch-all; если хостинг другой, применить эквивалент. Vite dev/preview могут возвращать SPA fallback: они не подтверждают production HTTP 404.
4. HTML содержит статические метаданные, но основной контент по-прежнему отрисовывается React на клиенте. Это не полный SSG/SSR. Для полного prerender нужен отдельный этап.
5. Отзывы, цифры, сертификаты, вакансии и тексты статей из прежнего аудита требуют фактических данных компании. Эта работа улучшает перечисленные best practices, но не подтверждает эти сведения и не пишет отсутствующие статьи.
6. Установка web-vitals сообщила о 20 уязвимостях в дереве зависимостей (1 low, 5 moderate, 14 high). Обновления с потенциальными breaking changes не выполнялись; нужен отдельный dependency audit.
